# Code Quality Rules

- Prefer readable, explicit, maintainable code.
- Keep functions and modules focused.
- Define interfaces at meaningful boundaries.
- Validate inputs early.
- Errors should contain useful context without exposing secrets.
- Avoid clever abstractions without a concrete need.
- Avoid giant functions and giant prompts.
- Do not mix unrelated refactors with feature work.
- Add tests with behavior changes.
- Update documentation when architecture, schemas, workflows, or operational behavior changes.
